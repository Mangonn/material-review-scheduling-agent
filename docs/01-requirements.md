# 01 需求与成功标准

## 用户与目标

内容团队需要识别待处理素材，了解审核风险和缺失资料，得到无冲突的发布时间建议，并保存可供人工确认的草稿。一次 CLI 请求处理一项素材；多项素材可连续调用，共用草稿数据库。

## 输入、输出和范围

- 输入：素材 ID、要求时段、硬/软要求、可选的明确替代时段确认。素材元数据、规则、已有排期来自 `data/` 中的合成 JSON。
- 输出：审核状态、风险原因、缺失字段、建议时段、待确认项、草稿保存状态、失败原因与 Trace。
- 动作：读取素材、检查规则、查询时段、保存草稿。没有真实平台发布接口。
- 假设：每个候选时段只能对应一项素材草稿；合成规则和排期由本地文件维护。

## 验收标准

| 场景 | 预期 |
| --- | --- |
| 正常排期 | 审核通过且时段空闲，保存一份草稿 |
| 素材信息缺失 | 列出缺失字段，不保存 |
| 规则风险 | 列出风险并阻断保存 |
| 时段冲突 | 补查替代时段；硬性要求变更待用户确认 |
| 重复提交 | 同一请求只留一份草稿 |
| 保存失败 | 明确失败，不声称已保存 |
| 达到上限 | 明确 `incomplete` 和原因 |

成功还要求每次保存前有审核通过与时段可用的工具证据，且 `published=false`。
