# 04 AI 使用与个人贡献

## 我的工作

我确定了素材审核与发布排期的业务目标和验收重点：18:00 被占用时可以建议 19:00，但硬性发布时间不能未经确认就改动；重复请求只能保存一份草稿；保存失败必须明确返回失败，不能称为已发布。我要求逐项核查代码、CLI 命令、离线 Mock 的边界和真实模型观察工具结果后的动作。

我创建公开 GitHub 仓库并提供真实模型运行条件。我审阅代码后，向 Codex 提出进一步修改意见：修复 Windows 测试中暴露的 SQLite 连接清理和并发测试同步问题，让软性时段调整也向用户明确提示，并补充真实模型保存失败的运行记录。我根据返回的测试与 Trace 核对了这些要求在交付材料中的呈现。

## AI 辅助范围与分工

我使用 Codex 完成需求细化、Python 代码、合成数据、测试、示例和文档的编写及修改；使用 DeepSeek 作为运行时动作决策模型。业务写入校验、幂等与确认边界由程序执行，不把模型或 Mock 的说法当作保存成功。Codex 负责具体代码修改、命令执行、故障排查和 GitHub 提交。离线 Mock 只验证流程，不能证明真实模型的决策效果。

Codex 在本地运行了 20 项自动测试和 8 组离线示例，并记录冲突、规则阻断、保存失败三条真实模型路径；实际结果见 03-evaluation.md 和 examples/。我提供验收意见并要求复核。
